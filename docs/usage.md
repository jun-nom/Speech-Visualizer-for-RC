# スピーチフロー可視化ツールの使い方

[公開版を開く](https://speech-visualizer-for-rc.pages.dev/)

## 初回の準備

- YouTube の動画と可視化ツールを Chrome の別タブで開きます。
- 可視化ツールの歯車から、OpenAI APIキーと Deepgram APIキーを入力して保存します。公開版で自動Miro描画を使う場合は、対象ボードの読み取り・編集権限がある Miro アクセストークンも入力します。トークンはこのタブを閉じるまで保持されます。
- Miro ボードに、発表ごとのタイトルと「スピーチ内容」を書き込む空間を用意します。配信の映像内に出る表記にタイトルをそろえると、同じ配信 URL に複数の発表が含まれる場合も照合しやすくなります。

## ライブ可視化を始める

1. 可視化ツールで自分のセッションを選ぶか、**新規セッション**を作ります。
2. **Miro会場**で対象のボード URL を入力し、**Connect** を押します。別のボードを使うときは、この欄の URL を変更して接続し直します。
3. **自動Miro描画**をオンにした状態で、**ライブ可視化を開始**を押します。
4. Chrome の共有ダイアログで YouTube のタブを選び、**タブの音声を共有**を有効にして共有します。YouTube を再生し、タイトル帯が表示される状態にします。Miro タブの共有は不要です。
5. 発話が既存の入力フォームに表示されます。フォームの横にある進捗表示で、受信件数、投稿先の発表名、Miro への投稿や整理の状況を確認できます。
6. 配信が終わったら **停止**を押します。残りの投稿や最終整理を行うため、処理状況が落ち着くまで可視化ツールのタブを開いておきます。

## 投稿と整理の動き

- 動画内上部の発表タイトルと Miro の見出しを照合します。タイトルが一致する枠を見つけられないときは、発話と映像の内容も手がかりにします。投稿先を特定できないときは発話を保留します。
- 話題の切れ目が見つかれば投稿します。途中でも約3分を目安に投稿し、新しい枠が確定すると最初の分を先に投稿します。
- 各発表の2回目の投稿から、AI が後続の発話やスライドを踏まえてカードや矢印を整理します。次の発表に切り替わった後も、前の枠の最終整理は続きます。
- 前の枠が埋まっているときは、投稿先の切り替えが確認できた時点で次の枠に進み、前の枠への保留分を再試行します。

## 文字起こしだけ使う

**自動Miro描画**をオフにして **ライブ可視化を開始**を押します。YouTube の音声を共有すると入力フォームに文字が入ります。必要な箇所を選び、**スピーチフローに追加**で手動でノード化できます。書き起こし済みのテキストを入力フォームに直接貼ってノード化することもできます。

## うまく進まないとき

| 画面の状態 | 確認すること |
| --- | --- |
| 発話の受信件数が増えない | YouTube を再生しているか、共有時にタブの音声を有効にしたか、Deepgram APIキーが有効かを確認します。 |
| 発表や書き込み先を特定できない | プレーヤー内に発表タイトルが表示されているか、Miro に対応する見出しがあるかを確認します。 |
| Miro へのアクセスエラーが出る | 入力した URL が正しいか、公開版の設定に入力したトークンでそのボードを読み取り・編集できるかを確認します。 |
| 話題を置ける空きがない | 対応する枠の「スピーチ内容」欄に空きがあるかを確認します。以前の試行で置いたカードも空き領域の計算に含まれます。 |
